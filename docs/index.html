§ 01Abstract

What if values could be retrieved?

Summary adapted from the paper's abstract; see the paper for its full text and limitations.

Memory Attention (MA) investigates replacing a dedicated attention value projection with learned token-indexed memory, complemented by context-dependent keys.

Each attention layer learns a token memory table; its retrieved representation contributes reusable token-specific information, while the key representation retains contextual information. At inference, row normalization can be folded into the memory table, leaving lookup and addition to construct values. CPU placement and prefetching provide a parameter-storage trade-off. Experiments report improvements in language modeling and average downstream scores under matched training-token budgets, with additional memory parameters.

§ 02Method

Memory instead of a value projection.

The contextual key used to form values is distinct from the RoPE-transformed key used in attention scoring.

Standard attention produces values with a learned dense projection. MA combines a pre-normalization content key with memory retrieved using the original token ID. Normalized rows may be precomputed for inference.

01 · ValueCore

Memory-based construction

Eliminates the independent V projection, using a layer-specific table and contextual keys instead.

02 · OffloadEvaluated

CPU memory, GPU compute

The token-indexed table may reside on CPU. Prefetching overlaps required lookups and transfers with computation while a conventional KV cache remains in use.

03 · RecallProposed

Reconstruct historical values

Retain sufficient K information and token IDs, then rebuild V on demand. This extension was not included in the paper's inference benchmarks.

§ 05Implementation

Built on Flash Linear Attention.

CPU-offload comparisons live in standalone profiling scripts, not the primary causal LM.

The public implementation exposes an MA layer and a Hugging Face-style causal language model. CPU-offload comparisons are currently in standalone profiling scripts; the repository README does not describe them as integrated into the primary causal LM implementation.
